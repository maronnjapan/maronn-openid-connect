# 地図を「経路をたどる地図」に作り直す

エンドポイントの画面と関数のページを、処理の流れの木を字下げした行で読むトレースにする。
呼び出しをその場で開いて何段下の関数まででもたどれ、分岐ごとに進む側を選べる。
道筋の列挙と、上限を超えたときの exit ケースは無くした。

処理の流れは、CLI の字句解析ではなく、新しい非公開パッケージ `packages/map-analysis` が TypeScript のコンパイラで読む。
PR の地図では変更前の木も作り、ノードと式の差分（「`<` を `<=` に変えた」）、届くエンドポイントと経路、外へ出る失敗の変化を計算する。
変更メモは意図と背景を書く場所になり、エンドポイントに届く変更とエンドポイントの処理本体の変更に説明の節が無いと、地図のビルドが落ちる。

この PR は地図とその解析だけを変え、関数カタログの関数とエンドポイントの処理は変えていない。

## 背景

これまでの地図は、関数のページをまたぐとたどった経路が途切れ、深い関数の変更をエンドポイントの画面から読めなかった。
ケースは道筋を列挙して作っていたため、条件の多い関数では上限で名前の無い exit ケースに畳まれ、全機能オンの `/token` では `authorization_code` と `refresh_token` を選べなかった。
設計は `apps/map/docs/design-change-trail-and-decision-cases.md` にある。
