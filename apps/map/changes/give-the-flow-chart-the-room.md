# フローの舞台を、ノートパソコンの画面でフローチャートに譲る

ノートパソコンの画面では、フローのフローチャートに箱が二つ見えるほどの高さしか残らず、流れを追いにくかった。
リクエストの欄を隠せるようにし、場面の説明をフローチャートの右に置き、図の操作を舞台の上の帯へ移して、フローチャートを広げた。

この変更は地図のページだけを変え、関数カタログの関数とエンドポイントの処理は変えていない。

## 背景

- 1366×768 の画面のブラウザ（表示域 1366×657）では、左の一覧（240px）とリクエストの欄（400px）の残りの 726px が舞台で、その高さをパンくず、再生の操作、図の操作、場面の説明が分け合い、フローチャートは 726×192 ピクセルだった。1440×900 の画面のブラウザでも 800×289 ピクセルだった
- 前の変更メモ（`flow-goes-where-the-reader-asks.md`）が「残ること」に挙げたとおりで、「画面いっぱい」で広げても、リクエストの欄の 400px は残った
- フローを読むのに常に要るのは、フローチャートと、いまの場面が何をしているかの説明である。リクエストの値は、書き換えるときに見えればよい

## 何を変えたか

- 舞台の上の帯に「リクエスト」を置き、リクエストの欄を隠したり出したりする。隠しても欄は描いたままなので、書きかけのリクエストや結果は残る。選んだ方は `localStorage` の `map.flowRequest` に残り、選んでいなければ幅 1600px 未満の画面では隠して開く。アウトラインの「地図の OP で試す」から開いたときは、その回は欄を出す
- 欄を隠している間、舞台が欄を指す所（実行できなかった理由、エンドポイントの処理が動かなかったリクエスト）に「リクエストの欄を開く」を添える
- 舞台の幅が 960px 以上なら、場面の説明をフローチャートの右の列に置き、再生の操作の下の高さを全部フローチャートに渡す。幅は画面ではなく舞台で測る（コンテナクエリ）ので、欄や左の一覧を出し入れすると置き場所も替わる
- 図の操作（向き、拡大縮小、幅、全体、戻す）を、フローチャートの上の一行から、上の帯のパンくずの横へ移した（`DiagramViewport` の `toolsIn`）。アウトラインの横の欄の図とスマートフォンでは、これまでどおり図のすぐ上に置く
- 舞台の大きさが変わったら、フローチャートは真ん中を真ん中に保ち、隠れた場面の箱を見える所へ戻す（`resizedCamera`、`DiagramViewport` の `steady`）。これまでは左上を保ったので、欄を隠したり「画面いっぱい」にしたりすると、フローチャートが左に寄った
- 低い舞台では、フローチャートを 100% より大きく開かない（`stageScale`）。左の一覧を閉じた 1366×768 の画面で `parseTokenRequest()` の中に入ると、一列のフローチャートを幅に合わせて 140% で開き、100% なら丸ごと見える五つの箱（始まりと終端を含む）が四つに減っていた

1366×768 の画面のブラウザでは、フローチャートは 766×381 ピクセル（左の一覧を閉じると 946×381、「画面いっぱい」で 946×491）になり、場面の説明は右の列で全部読める。

## 確かめたこと

- `e2e/layout.spec.ts` が、幅 1440px で欄が隠れて開き、場面の説明がフローチャートの右に、図の操作が再生の操作の上にあること、「リクエスト」で欄を出すと場面の説明がフローチャートの下へ移ること、選んだ方が再読み込みの後も残ること、エンドポイントの処理が動かなかったリクエストを開くと「リクエストの欄を開く」で欄と応答を出せることを、地図の Worker で確かめる。ほかの E2E は、`openFlow` が欄を出してから操作する
- `src/lib/camera.test.ts` が、`stageScale` と `resizedCamera` を確かめる

## 残ること

- 欄を出したノートパソコンの画面では、舞台が 960px に届かないので場面の説明はフローチャートの下に戻り、フローチャートの大きさはこれまでとほぼ同じになる。書き換えながら道筋を見るときは、そのぶん狭い
- 再生の操作は三行（道筋の選択と呼び出しの中、再生のボタンとつまみ、追っているリクエストの一行）で、低い画面でも 117px を使う
