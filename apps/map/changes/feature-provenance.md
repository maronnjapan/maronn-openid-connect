# フラグと実装・テストの対応を見えるようにする

機能をオンにした状態でも、共有エンドポイントのどこからどこまでがその機能の処理なのかを読めるようにする。エンドポイント・手順・直接所有する実装に機能の札を出し、ソースの行には生成器と同じ owner block の境界を使う。

呼び出し先をすべて機能専用とする方法では、共有の認証や JWT の関数まで PAR の実装に見えてしまう。そのため所属は登録済み機能の専用ディレクトリ、エンドポイントの定義、owner block、テストの直接の対象と明示指定から求め、呼び出しの到達関係からは伝播させない。ライブラリの機能専用コードも「機能の実装」と示し、生成されるファイルとは言い切らない。

追加するデータは optional とし、古い地図・テストデータでは札を出さず既存の表示を維持する。Provider と CLI の生成結果・認可の振る舞いは変更しない。
