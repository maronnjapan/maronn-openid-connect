# フローで、書いたリクエストを地図の OP で動かし、通った道筋を再生する

フローの「リクエスト」欄を、クエリ、ボディ、ヘッダーを書いて実行する欄にした。
ケースを選ぶと、そのケースを通ったテストが送ったリクエストから始まり、値を書き換えて実行できる。
実行すると、ページの Web Worker で `apps/hono` の OP（全機能オン、テストと同じ前提）が動き、通ったコードの Istanbul の計数を、テストカタログがテストのリクエストを読むのと同じ規則で読んで、各フレームの決定の側を決める。
「道筋」は「実行したリクエストが通った道筋」になり、失敗したときは投げた関数のフレームまで開いて、最初から再生する。

この変更は地図とその解析、地図の OP（`packages/map-sandbox`）だけを変え、関数カタログの関数とエンドポイントの処理は変えていない。

## 背景

これまでの「リクエスト」はテストが送ったものを出すだけで、値を変えたら道筋がどう変わるかは、コードの分岐の側を読者が選び直して確かめるしかなかった。
リクエストから道筋を求めるのに、条件の式をリクエストの値から読み解く方法は、ストアや署名を挟む値を追えず推測になる。
地図が描いているコードをそのまま動かし、テストの例と同じ規則で読めば、テストが見るのと同じ道筋が出る。
