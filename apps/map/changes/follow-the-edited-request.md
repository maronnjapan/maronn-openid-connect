# リクエストを書き換えると、送る前にフローがその道筋に替わる

地図のフローの「リクエスト」でパラメータ、ヘッダー、ボディを書き換えると、送る前に、右のフローチャートと再生が書き換えたリクエストの道筋に替わるようにした。
書き換えたリクエストは、地図の OP がワークスペースのいまの状態のコピーで動かし（`POST /__live/preview`、試算）、コピーごと捨てる。
再生はその試算が動かした順を、送ったリクエストと同じようにたどる（`followTrace`）。
ケースが準備したリクエストも、選んだときに試算して、その道筋をすぐに再生する。
結果の欄は「送る前の試算（地図の OP の今の状態のコピーで動かしました。OP の状態は変えていません）」として、ステータス、OAuth のエラー、`Location`、終わり方を出す。
「このリクエストを実行」は、これまでどおり地図の OP に送り、フローは送った交換の道筋に替わる。
「想定リクエスト」の選択は、書き換えても変わらない。

この変更は地図のページだけを変え、関数カタログの関数とエンドポイントの処理は変えていない。
試算の API（`POST /__live/preview`、`LiveOpClient.preview`）は `packages/live-op` に先に足した。

## 背景

これまでは、リクエストを書き換えても、実行するまでフローは前の道筋（ケースを選んだだけなら「おまかせ」の仮の側）のままだった。
書いたリクエストとフローの道筋が食い違うので、どの値がどの分岐を決めているのかを、書き換えながら確かめられなかった。
実行すれば道筋は替わるが、OP は状態を保つので、送るたびに認可コードを使い切り、ログインの失敗を数え、準備し直しが要った。
試算はワークスペースの状態を変えないので、同じ認可コードで `code_verifier` を何度書き換えても、それぞれの道筋（PKCE の照合で失敗する、成功する）を見比べられる。

## 何を変えたか

- 書き換えてから 0.4 秒書かなかったときに一度だけ試算する。結果が来るまで前の道筋を出したまま「試算中…」と添える。新しい試算を頼むと前の試算の要求は取り消し（`LiveOpClient.preview` に足した `signal`）、後から来た古い結果も捨てる
- 試算で道筋が替わっても、再生は自分では始めず（再生中なら止まり）、いまの場面が残っていればそこにとどまる。実行したときは、これまでどおり最初から再生する
- 空欄のままのリクエスト、「最近のリクエスト」から開いたままのリクエスト、実行したままのリクエストは試算しない。書き換えた後で、開いたリクエストや実行したリクエストに戻すと、その記録の道筋に戻る
- 空欄から書いたリクエストを空欄に戻すと、試算をやめ、書き始める前の道筋（選んでいた道筋かおまかせ、その前に実行したか開いたリクエストの記録）に戻る。空欄を試算しないのは、空欄は読者が書いたリクエストではなく、「元のリクエストに戻す」は書き始める前に戻すことだからである
- 送れない形に書き換えたリクエスト（GET のボディ、名前に使えない文字のヘッダー）は試算せず、出したままの結果に「この結果は書き換える前のリクエストのものです」と添える
- 送っている間は試算しない。送っている間に書き換えたリクエストは、送った結果を出してから、送ったリクエストと違えば試算する。送っている間に試算が結果を置き換えて、送った応答が出ないことはない
- 試算が地図の OP に届かなかったことは一つの警告で出し、次の書き換えでまた試算する。警告は、試算、実行、開いたリクエストのどれかが届くと消える
- 側を選んで試算の道筋から離れた後は、試算が来たとき（か「このリクエストの道筋に戻す」）だけまた従う。書いてすぐ消した書き換えでは試算せず、離れたままにする
- 試算は交換の一覧にも、URL のハッシュにも残らない（交換の `;x=` も、試算の道筋の `;d=` も書かない。`TraceState.previewed`）。再読み込みすると、試算の道筋を「自分で選んだ道筋」として出していた
- Next.js の地図と、地図の OP に接続できないときは試算しない
- 記録の出どころ（「x4 で変更」）は、一つの交換が同じ記録を二度変えても一度だけ出す。デバイスの承認（`/device/approve`）はデバイスコードを二度書くので、`token-device-approved` のケースで React が同じ key の警告を出していた。重なりはワークスペースの `noteProvenance` が交換を変更ごとに足すことから来ていて、地図のページで一度にまとめる（`changersOf`）

## 残ること

- 試算の要求を取り消しても、地図の OP の側では動き終わるまで動く（読者のワークスペースの状態のコピーで動くので、残るものは無い）
- 試算は、OP が外へ送るリクエスト（クライアントの `jwks_uri`、`request_uri`）を、送ったときと同じく本当に送る
- 書き換えの途中で送れない形になったリクエスト（GET のボディ、名前に使えない文字のヘッダー）は試算せず、フローは前の道筋のままである（結果にはそう添える）
- 記録の出どころの重なりは、ワークスペースの `noteProvenance`（`packages/live-op/src/workspace.ts`）が直せば、ページでまとめなくてもよくなる
