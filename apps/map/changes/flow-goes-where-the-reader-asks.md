# フローが、読者の操作とリクエストの書き換えに合わせて動く

地図のフローで、呼び出しの中へ進むボタンが中へ進まず、リクエストを書き換えても再生が動かないことが多かった。
フローを、押したらそこへ行き、書き換えたら変わった所を見せるように直し、画面をリクエストの側とフローの舞台に分けた。

この変更は地図のページだけを変え、関数カタログの関数とエンドポイントの処理は変えていない。

## 背景

- 場面の「中に入る ▸」と、フローチャートの箱のカードの「中の流れを見る（図がその関数に移る）」は、呼び出しのフレームを開くだけだった。フローのフローチャートはいつも再生の場面のフレームを描くので、再生が呼び出しの場面にいる間は何も変わらず、押しても中に入れないように見えた。このリクエストが通らない呼び出しは、中を見る手段が無かった
- 書き換えたリクエストの試算は届いていたが、再生が動くのは、書き換える前のリクエストと読み比べて分かれる場所があるときだけだった。空欄から書いたリクエストは読み比べないので、道筋が失敗に替わっても再生は最初の場面のままで、変わったのは先の箱の色だけだった
- 書き換えたリクエストを実行すると、再生は最初の場面から始まった。イントロスペクションの有効なアクセストークン（JWT）の先頭の `ey` を消して送ると、OP はトークンを見つけられずに `{"active":false}` を返すが、ステータスは同じ 200 で、エンドポイントのステップも同じなので、`resolveIntrospectionToken()` の `if (at)` が不成立になる場面に着くまでの 30 秒ほど、書き換える前と同じ場面が続き、フローがそのまま通ったように見えた
- 再生の操作、場面の説明、リクエストの欄、応答、最近のリクエスト、地図の OP の状態が、幅 380px の一列に詰まり、それぞれが小さなスクロールを持っていた。リクエストを書く欄と応答はその下のほうにあり、ノートパソコンの画面では、書き換えながら応答を見られなかった

## 何を変えたか

- 「中に入る ▸」と「中の流れを見る」は、フレームを開いたうえで、再生をその中の最初の場面へ移す。フローチャートはその関数のものに替わる。呼び出しの場面では「中へ進む ▸」で中へ進み、「中を閉じる」で戻す
- このリクエストが通らない呼び出しは、その関数のフローチャートだけを灰色で出し、上の帯に「このリクエストは … を通りません。中の流れだけを見ています。」と「再生の場所に戻る」を出す。再生を動かすか、パンくずで再生が通った関数を押すと戻る
- 書き換えたリクエストの道筋が替わったら、再生はその道筋が前の道筋から離れる場面へ移る。書き換える前と読み比べたときはこれまでどおり分かれる最初の場面、そうでなければ前の道筋も通った分岐を違う側へ進む最初の場面、それも無ければ前の道筋に無かった失敗の場面（`departureScene`）。ケースが準備したまま、開いたままのリクエストは書き換えではないので、場面を動かさない（`RequestRunDone.edited`）
- 書き換える前と読み比べたリクエストを実行したときは、二つが分かれる最初の場面から再生する（それ以外の実行と、開いたリクエストは、これまでどおり最初から）
- 再生を移すのは、トレースがその道筋を出し終えてから（`RequestRun.shows`：再生が読んだ側を選び、開くフレームを開き、前の再生のフレームを閉じ、要る木を読み終えた）にした。新しい道筋を出す途中の場面で比べると、前の道筋の場面のまま移っていた
- 結果が来てから読者が再生を動かしたら（◀ ▶、End、つまみ、箱、分かれる所のボタン）、フローは後から再生を移さない。道筋を読み終えるのを待って移すので、先に End を押した読者を、分かれる所へ引き戻していた
- 舞台の上の一行に、短いボディ（`{"active":false}`）と、書き換える前と分かれる所（か、同じ道筋であること）を出す。同じ 200 でも、何が変わったかが一行で分かる
- 画面を、左のリクエストの側（想定リクエスト、リクエストの欄と応答、最近のリクエスト、地図の OP の状態を一つのスクロールで）と、右の舞台（再生の操作、フローチャート、いまの場面）に分けた。舞台の上の一行に、追っているリクエストの応答（ステータスと OAuth のエラー）と道筋の終わり方を出し、終わり方を押すと最後の場面へ移る。スマートフォンでは舞台、リクエストの順に一列に並べる
- 速さに 4× を足した。呼び出しを二段開くと /token の道筋は 200 場面を超え、2× でも通して見るのに 4 分かかる

## 確かめたこと

- `e2e/flow.spec.ts` が、場面と箱のカードから中へ進むこと、通らない呼び出しの中だけを見て戻ること、空欄から書いたリクエストが失敗する `requireClientId()` へ再生が移ること、先頭の `ey` を消したトークンのイントロスペクションが、試算でも実行でも `resolveIntrospectionToken()` から再生され、舞台の上に `{"active":false}` と分かれる所が出ることを、地図の Worker で確かめる
- `src/lib/playback.test.ts` が、`departureScene` の分岐の側の違い、前に無かった失敗、比べられないフレームを確かめる

## 残ること

- 書き換えのたびに場面が移るので、書き換えながら同じ場面を見続けたいときは、移った後で戻す必要がある
- 舞台は高さを再生の操作と場面の説明に分けるので、高さ 720px の画面ではフローチャートが 200px ほどになる。「画面いっぱい」で広げられる
